# 止盈委托暴露量检查修复

**修复时间**: 2026-03-13 00:14  
**问题**: 止盈委托被误判为补仓，触发暴露量限制  
**根本原因**: 平仓委托（reduce_only=True）不应该受暴露量限制  
**解决方案**: 平仓委托跳过暴露量检查

---

## 问题描述

### 错误日志
```
2026-03-13 00:14:24 | INFO | [ORDER] 创建止盈委托：SELL 0.0640 @ 70414.93 (止盈/止损) - 持仓方向：LONG
2026-03-13 00:14:24 | WARNING | 暴露量超限：持仓=0.0640, 现有委托=0.0000, 新委托=0.0640, 总计=0.1280, 限制=0.1000, 可用=0.0360
WARNING: [ORDER_SUBMIT] symbol=BTCUSDT reason=EXPOSURE_LIMIT_EXCEEDED size=0.0640, available=0.0360
WARNING: [ORDER] 止盈委托提交失败：EXPOSURE_LIMIT_EXCEEDED
```

### 问题分析

**错误逻辑** ❌:
```
持仓：LONG 0.0640 BTC
止盈：SELL 0.0640 BTC (reduce_only=True, 平仓委托)

暴露量检查:
  总暴露量 = 持仓 0.0640 + 新委托 0.0640 = 0.1280 ❌
  限制 = 0.1000
  结果：超限，拒绝委托 ❌
```

**问题根源**:
- ❌ 暴露量检查没有区分**平仓委托**和**开仓委托**
- ❌ 止盈委托是**反向平仓**，不应该增加暴露量
- ❌ 错误地将平仓委托计入暴露量

---

## 正确逻辑

### 暴露量计算规则

**开仓委托** (reduce_only=False):
```
总暴露量 = 当前持仓 + 现有未成交委托 + 新委托
```

**平仓委托** (reduce_only=True):
```
总暴露量 = 当前持仓 + 现有未成交委托
(新委托不计入，因为它是平仓，会减少持仓)
```

### 正确计算示例

```
场景：LONG 0.0640 BTC，创建止盈委托 SELL 0.0640

正确计算:
  当前持仓 = 0.0640
  现有委托 = 0.0000
  新委托 = 0.0640 (但这是平仓委托，不计入)
  
  总暴露量 = 0.0640 + 0.0000 = 0.0640 ✅
  限制 = 0.1000
  结果：未超限，允许委托 ✅
```

## 注意事项

### ⚠️ 1. 正确设置 reduce_only 参数

```python
# 止盈委托：reduce_only=True ✅
order_executor.open_position(
    side="SELL",  # 与持仓相反
    reduce_only=True  # 必须设置
)

# 补仓委托：reduce_only=False ✅
order_executor.open_position(
    side="BUY",  # 与持仓相同
    reduce_only=False  # 必须设置
)
```

### ⚠️ 2. 平仓委托不需要暴露量检查

**原因**:
- 平仓委托会**减少**持仓，不会增加风险
- 平仓后暴露量会**降低**，不会升高
- 因此不需要检查暴露量限制

### ⚠️ 3. 开仓委托必须检查暴露量

**原因**:
- 开仓委托会**增加**持仓和风险
- 需要确保总暴露量不超过限制
- 防止过度暴露
