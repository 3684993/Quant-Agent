## 🔴 发现的新问题

### 问题 1: **重复委托检查逻辑错误** 🔴

**现象**:
```
17:40:24 | Order cancelled: 12764933001
17:40:25 | 发现重复委托：价格=69685.60 vs 69708.20, 数量=0.0200 vs 0.0200
17:40:25 | 发现重复委托，跳过执行：long 0.02 BTCUSDT @ 69708.2
17:40:25 | ORDER_REPLACE: BTCUSDT old=12764933001 reason=timeout new_price=69708.20 success=False
```

**问题分析**:
1. 订单 `12764933001` 在 17:40:24 被取消
2. 系统尝试下新订单 (价格 69708.20)
3. 但是"重复委托检查"认为有新订单与旧订单重复
4. **实际上旧订单已经被取消了，不应该被认为是"重复委托"**

**根因**: 
- 重复委托检查可能基于内存中的 `pending_orders` 字典
- 订单被取消后，`pending_orders` 没有及时清理
- 导致系统错误地认为订单仍然存在

**影响**:
- 订单超时取消后，无法重新下单
- 系统陷入"取消 → 尝试下单 → 被阻止 → 取消"的死循环
- **无法完成建仓**

### 问题 2: **订单无法成交** 🟡

**现象**:
```
17:37:05 | Order executed: 12764933001 - NEW
17:37:05 | 价格：69685.60
17:40:24 | 当前价格：69808.20
17:40:24 | Order cancelled: 12764933001 (200 秒后取消，未成交)
```

**问题分析**:
- 订单价格 69685.60，市场价最高到 69808.20
- 订单是**限价买单**，价格低于市场价
- 市场价格没有回调到订单价格，所以无法成交

**可能原因**:
1. 订单价格计算过于保守（价格偏离市场价太多）
2. 没有使用市价单 fallback 机制
3. 价格调整不够积极

# 在订单取消后，清理 pending_orders
def cancel_orders(self, symbol: str, order_ids: List[str]):
    for order_id in order_ids:
        # 取消订单
        result = self.binance_client.cancel_order(symbol, order_id)
        
        # 清理 pending_orders

### 修复 3: 添加 task.active_orders 清理

**问题位置**: `execution_tracker.py` 或 `execution_engine.py`

**修复建议**:
```python
# 在 refresh_task 方法中
def refresh_task(self, task, binance_client, order_executor):
    for order_id in list(task.active_orders.keys()):
        # 获取订单状态
        detail = binance_client.get_order_by_id(task.symbol, order_id)
        
        # 如果订单已取消或已完成，从 active_orders 中移除
        if detail.get("status") in ["FILLED", "CANCELED", "REJECTED", "EXPIRED", "UNKNOWN"]:
            task.active_orders.pop(order_id, None)
            logger.info(f"ACTIVE_ORDER_CLEANUP: {task.symbol} order_id={order_id} status={detail.get('status')}")
```
